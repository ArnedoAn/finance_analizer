# API endpoints v3

Mount under /api/v1. X-API-Key is required except health/live, health/ready and POST devices/enroll (one-time code instead of a key). Device keys are looked up by sha256 hash (see dependencies.authenticate); scopes ingest/read/review/admin, one per route (`require_scope`, or `required_scope="enroll_code"` for the enroll route). FINANCE_API_KEY (>=32 characters) is the server-side admin; PHONE_API_KEY is optional and adopted as the ingest device `phone-legacy` on first valid use. Enrollment codes expire in 10 minutes, are stored hashed and are claimed with an atomic UPDATE ... WHERE used_at IS NULL; enroll/revoke call audit.record. Ten invalid keys or enrollment codes per socket-peer IP per minute trigger 429 for further invalid attempts; valid keys always pass and never clear the failure bucket. Share get_db so tests can override it. Commit webhook ingestion before background processing in a fresh session, return inbox_id for accepted and duplicate/ignored events, and retain truncated raw text according to the v3 retention policy. Every error is JSON `{detail, code}` (main.py handlers; a route picks its code with `HTTPException(status, {"detail": ..., "code": ...})`, otherwise it derives from the status; 429 keeps Retry-After). Unexpected errors return sanitized JSON 500 responses.

Inbox responses use an explicit public field allowlist and never expose claim_token, claim_until, or future internal columns. Only admin GET inbox/{item_id}?include_raw=true returns raw_text; the default is false. Lists, manual transactions, review actions, and reprocess responses omit raw_text. Manual requests require client_ref, validate before processing (422), and return 502 with the durable failed inbox_id on submission failure; do not automatically retry manual failures. Review supports approve/reject/edit/void and reprocess; updates and voids propagate to Firefly. Sender learning only proposes pending approvals; /senders/seed does not exist.

GET health reads IMAP last_poll_at and consecutive_failures from the database without logging into mail. Never-polled accounts or polls older than two hours are stale and degrade health; any consecutive failure also degrades health. Explicit POST mail/accounts/{name}/test reserves one login per account per minute atomically in the notifications table with key mail-test:{name}, committed before IMAP login; repeated tests return 429 with Retry-After: 60. This reservation never creates alerts. Production disables docs/OpenAPI unless EXPOSE_DOCS=true. Public probes must never expose secrets.
